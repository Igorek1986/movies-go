# Разработка расширений для movies-go

Расширение — это один JS-файл, который пользователь подключает по ссылке на странице `/profiles` → «Расширения». После подключения он появляется в Настройках как собственный пункт — со своей формой, кнопками, чем угодно. Расширение ничего не знает о внутренностях сайта: у него есть только маленький API (`window.Ext`) для общения с сервером, и всё.

Готовые рабочие примеры — `plugins/timecode_import_lampa.js` и `plugins/timecode_import_lampac.js` в этом репозитории. Если непонятно что-то из написанного ниже — проще всего открыть один из этих файлов рядом.

## Быстрый старт

1. **Создайте JS-файл.** Это обычный `<script>`, без импортов, без сборки — то, что внутри, выполнится как есть. Оберните код в `(function () { ... })()`, чтобы не мешать другим расширениям.

2. **В конце обязательно вызовите `Ext.ready(...)`** — это сигнал «я загрузился и отрисовался». Без него в интерфейсе так и останется индикатор загрузки.

   ```js
   (function () {
     'use strict';

     var p = document.createElement('p');
     p.textContent = 'Привет из расширения!';
     document.body.appendChild(p);

     Ext.ready({ title: 'Моё первое расширение' });
   })();
   ```

3. **Положите файл туда, откуда его можно скачать по ссылке.** Проще всего для разработки — папка `./plugins/` этого репозитория: файл `plugins/hello.js` сразу становится доступен по адресу `/hello.js` на локально запущенном сервере, без пересборки и без перезапуска (см. `servePlugins` в `internal/api/router.go`).

4. **Подключите.** Зайдите в `/profiles` → «Расширения» → вставьте `/hello.js` в поле «Ссылка на расширение» → «Добавить расширение». Сервер сразу проверит, что файл отвечает 200 и похож на JS (не HTML-страницу).

5. **Готово** — расширение появится отдельным блоком под списком, со своим заголовком и текстом «Привет из расширения!» внутри.

Дальше меняете файл — просто обновите страницу браузера, пересборка не нужна.

## Как это устроено внутри (коротко)

Расширение выполняется не на самой странице, а в отдельном `<iframe sandbox="allow-scripts">` без `allow-same-origin`. Это значит: у него нет доступа ни к cookie сайта, ни к его DOM, ни к localStorage — только к своему собственному пустому документу. Всё, что расширению нужно от сервера (список устройств, создание профиля и т.п.), идёт через `window.Ext` — тонкую обёртку над `postMessage`.

Практический смысл этого для вас: пишите обычный HTML/DOM/JS внутри своего расширения как на любой веб-странице (`document.createElement`, `addEventListener`, формы, всё как обычно) — просто вместо `fetch('/api/...')` к нашему сайту используйте `Ext.call(...)`.

## API: `window.Ext`

Доступен сразу, как глобальная переменная — ничего подключать не нужно.

### `Ext.ready(meta?)`

Обязательный вызов в конце. `meta.title` (необязательно) задаёт заголовок блока — если не передать, используется имя, под которым пользователь добавил расширение.

### `Ext.call(action, params?)` → `Promise`

Единственный способ обратиться к серверу. Возвращает промис: резолвится результатом, реджектится с текстом ошибки (в том числе если сервер не ответил за 15 секунд — зависнуть навсегда с "висящей" кнопкой невозможно).

```js
Ext.call('devices.list').then(function (r) {
  console.log(r.devices); // [{id, name}, ...]
});
```

`action` — не произвольная строка, а один из фиксированного списка ниже. Это **не** прокси к любому эндпоинту сайта — список закрытый и жёстко проверяется на сервере (`internal/api/web_extensions_rpc.go`). Если вашему расширению нужно что-то, чего в списке нет — это требует правки бэкенда (добавить новый `case` в тот файл), написать это только на JS-стороне нельзя.

| `action` | `params` | что вернёт | что делает |
|---|---|---|---|
| `devices.list` | — | `{devices: [{id, name}]}` | устройства текущего пользователя |
| `devices.create` | `{name}` | `{id, name}` | создать устройство (действуют те же лимиты по роли, что и в обычных Настройках) |
| `profiles.list` | `{deviceId}` | `{profiles: [{profile_id, name, icon, ...}]}` | профили устройства (устройство должно принадлежать пользователю) |
| `profiles.create` | `{deviceId, name}` | `{profile_id, name}` | создать профиль |
| `timecodes.importLampac` | `{deviceId, profileId, data}` | `{imported: N}` | импорт таймкодов; `data` — `{card_id: {item: "JSON-строка данных"}}` |

### Пример посложнее — форма с выбором устройства

Реальные расширения обычно устроены так: список устройств → пользователь выбирает → делаем что-то с этим устройством. Вот минимальный, но полный пример этого паттерна (без обработки ошибок — в реальном коде добавьте `.catch(...)`, см. готовые плагины):

```js
(function () {
  'use strict';

  var select = document.createElement('select');
  var button = document.createElement('button');
  button.textContent = 'Создать профиль «Тест»';

  Ext.call('devices.list').then(function (r) {
    r.devices.forEach(function (d) {
      var opt = document.createElement('option');
      opt.value = d.id;
      opt.textContent = d.name;
      select.appendChild(opt);
    });
  });

  button.onclick = function () {
    var deviceId = Number(select.value);
    Ext.call('profiles.create', { deviceId: deviceId, name: 'Тест' }).then(function (p) {
      alert('Создан профиль: ' + p.name);
    });
  };

  document.body.appendChild(select);
  document.body.appendChild(button);
  Ext.ready({ title: 'Пример с формой' });
})();
```

## Если что-то не работает

Любая необработанная ошибка в вашем коде (опечатка, исключение) **сама покажется красным баннером** прямо в теле расширения — открывать консоль браузера не обязательно. Если баннера нет, а расширение просто ничего не делает при клике — скорее всего, ошибка гасится вашим же `try/catch` или `.catch()` без вывода; временно уберите его и посмотрите, что покажется.

Высота блока подстраивается под содержимое сама — ничего для этого делать не нужно.

## Как выглядят элементы (стили)

Обычные `input`/`select`/`textarea`/`button` уже стилизованы под тему сайта — рисовать им ничего не нужно, просто создавайте элементы. Пара готовых классов, если понадобятся:

- `class="row"` — располагает несколько полей в один ряд (например, «устройство» + «профиль» рядом). Без этого класса блочные элементы лягут друг под другом.
- `class="alert alert-success"` / `class="alert alert-error"` — заметный баннер под статус операции (зелёный/красный, с фоном). Пустой `.alert` (без текста) сам не показывается — держите один и тот же элемент, просто меняйте `className`/`textContent`.
- `class="copied-hint"` — маленькая зелёная надпись-подтверждение (для сценария «нажал — скопировалось», см. пример ниже).

CSS-переменные сайта (`--color-*`) внутрь расширения не попадают — это отдельный документ. Если нужного класса нет — используйте свои цвета, но обычно готовых хватает.

## Буфер обмена

`navigator.clipboard.writeText()` разрешён, но не гарантированно работает во всех браузерах/ситуациях. Рекомендуемый паттерн — с фолбэком:

```js
function copyToClipboard(text) {
  if (navigator.clipboard && navigator.clipboard.writeText) {
    navigator.clipboard.writeText(text).catch(function () { execCommandCopy(text); });
  } else {
    execCommandCopy(text);
  }
}

function execCommandCopy(text) {
  var ta = document.createElement('textarea');
  ta.value = text;
  ta.style.position = 'fixed';
  ta.style.opacity = '0';
  document.body.appendChild(ta);
  ta.focus();
  ta.select();
  try { document.execCommand('copy'); } catch (e) {}
  document.body.removeChild(ta);
}
```

Полный пример с визуальным подтверждением («Скопировано!» на 1.5 секунды) — `plugins/timecode_import_lampa.js`.

## Публикация (не только для разработки)

Расширению не обязательно жить в `./plugins/` этого сервера — это удобно только для разработки/первичных расширений. Любой `https://` URL подойдёт, если он отдаёт сам JS-файл (не HTML-страницу с ошибкой) с кодом 200 — сервер проверяет это при добавлении ссылки.

## Ограничения (пока)

- Никакого манифеста — только один JS-файл. Имя/иконка — то, что ввёл пользователь при добавлении, либо `Ext.ready({title})`.
- Список `action` в `Ext.call` — общий для всех расширений, персональных прав доступа нет.
- Обновление файла на вашем сервере сразу применяется у всех, кто подключил его по этой ссылке — версионирования нет.
